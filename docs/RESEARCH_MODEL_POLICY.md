# Research Model Policy

## Purpose

Radiocity distinguishes exploratory software, simplified engineering abstractions, validated physical models, and empirical evidence. This separation is essential for defensible research claims.

## Evidence hierarchy

1. **Experimentally validated** — supported by reproducible measurements from a described physical setup.
2. **Independently checked physical model** — supported by physical equations, numerical verification, and an independent reference or calculation.
3. **Calibrated engineering model** — parameterized against published or measured data, with calibration limits disclosed.
4. **Sensitivity model** — simplified to explore parameter dependence, not a calibrated device prediction.
5. **Illustrative software prototype** — demonstrates data flow or architecture but is not yet evidence of physical performance.

Passing a software test validates the tested software behavior only; it does not validate the physical assumptions.

## Thermal / TPV policy

The earlier wavelength-dependent 40%/20%/0% TPV efficiency function is retained only for provenance and sensitivity analysis. It must not be presented as experimentally validated TPV performance.

The literature-anchored TPV efficiency envelope is also a sensitivity/engineering model unless calibrated to a specific device and operating conditions. A future device-level TPV model should account for spectral response, bandgap, sub-bandgap losses, voltage/current losses, radiative recombination, parasitic heat transfer, and thermal balance using suitable published data.

## RF / EMR policy

Ambient RF contribution must be calculated from defensible incident power density, frequency, effective capture area, antenna/rectenna response, and conversion efficiency. Do not imply that ordinary ambient Wi-Fi or cellular fields provide substantial power without quantitative support. The current RF channel is a simplified abstraction, not a full-wave or measured rectenna model.

## LightGBM / PSO policy

LightGBM is currently trained on synthetic samples generated by the physics model. Its outputs approximate that model and inherit its assumptions; this is not independent empirical validation. Report held-out surrogate error, sample-generation bounds, random seed, and training configuration.

PSO outputs are candidate operating points, not guaranteed global optima. Report bounds, seed, convergence behavior, feasibility checks, and a comparison with grid search or a fixed baseline. Always distinguish surrogate-predicted power from physics-validated power.

## Dynamic simulation policy

Synthetic time-varying source profiles are controlled test scenarios, not field observations. The current dynamic intelligent simulation consumes thermal and RF profile fields. Solar irradiance can be represented in a profile but is not yet connected to a PV conversion path. NF-TPV, physical gap/filter actuation, and reinforcement learning remain future work.

## Result policy

Each quantitative result intended for a paper should record:

- code version / commit;
- source and receiver conditions;
- source profile and its provenance;
- spectral/frequency ranges and numerical methods;
- collection and conversion assumptions;
- thermal/storage constraints;
- baseline definition;
- random seeds and optimization settings;
- uncertainty and sensitivity;
- whether the evidence is synthetic, simulated, calibrated, independently checked, or experimental.

Historical results remain useful for provenance but should be marked superseded when core assumptions change. No performance improvement should be claimed without a fair baseline comparison.
